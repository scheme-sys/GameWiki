# 玩家数据清理与维护

本项目只保留玩家资料和网站功能需要的数据。当前维护源与发布数据都已清除未使用的游戏实现信息；界面隐藏不能代替文件清理。

## 保留哪些内容

- 游戏名称、版本、物品与角色说明、数值、等级变化、能力、配方、掉落、任务及指南。
- 收藏、分享链接、配方材料和详情跳转使用的稳定 ID 与关联关系。
- 本地图片路径，以及 3D 预览实际使用的部件、网格、材质、纹理映射。
- 图片字节摘要、清理后数据摘要、数量及必要的维护校验信息。

关联 ID、统计键和模型映射是网站的数据结构。它们不代表页面包含游戏程序实现，也不能因为看起来像技术字段而全部删除。

## 已清理哪些内容

- 不参与网页功能的游戏函数引用、函数原型/行号和内部类名。
- 未使用的原始配置副本、内部本地化键、审计和来源字典。
- 原始资源包名称、提取路径、资源包对象地址及与页面无关的工具路径。
- 仅用于内部技术搜索的词条，不再参与玩家搜索。

清理同时覆盖维护 JSON、运行时 JavaScript、来源报告及不用的旧工具实现。保留下来的维护浏览器只使用可读名称与本地图片路径；旧导入入口不能把未筛选的游戏记录重新覆盖回来。

各游戏工具依据自己的字段结构进行清理或校验。原始游戏记录不可直接覆盖当前数据。新增玩家字段应同时核对显示、导出和关联需求，再调整对应字段白名单。

## 验证与发布

在仓库根执行：

```sh
node scripts/test-player-data-policy.mjs
node scripts/check-player-data.mjs
node scripts/check-site.mjs
```

日常检查直接读取源码，不生成整站副本；测试夹具使用自动清理的临时目录。全局检查覆盖已登记游戏目录中的维护 JSON、浏览器数据脚本、中文 CSV 和指南，识别已知的实现信息残留，也会拒绝数据对象中混入可执行函数。网页自身的交互脚本不属于游戏程序，不按游戏函数处理。

全局模式检查是补充防线，不代替各游戏的字段白名单、图片与玩家数值校验，也不是通用的凭据或秘密扫描器。修改生成、导入流程时，应运行对应游戏 README 中的检查，并验证搜索、详情、收藏、配方、导出和模型功能。

GitHub Actions 在打包前检查维护源，在打包后检查最终站点，两处失败都会阻止发布。

## 公开内容和历史版本

玩家浏览所需的图片、资料及网站 JavaScript 仍会发送给浏览器，可以被访问者下载。本次清理减少多余的内部信息，不会让公开静态网页的数据变成私密内容。

修改当前文件不会自动删除 Git 历史、已有分叉、旧下载或旧的部署产物。清理后的版本需要提交、推送并成功部署，线上站点才会更新；旧副本不会被撤回。本次没有改写 Git 历史，也没有删除远程仓库或远程发布记录。

本地不保留验证快照、历史发布副本或默认测试截图。确需检查打包结果时使用临时目录，结束后清理；只有明确需要保留浏览器诊断输出时才设置 `LCZ_TEST_OUTPUT`。`.verification/` 仍被 Git 忽略，且不进入站点发布包，不应强制加入仓库。
