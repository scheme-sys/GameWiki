## 浏览和发布

在仓库根执行 `python -m http.server 4173`，打开 `http://127.0.0.1:4173/LDOE_Wiki/`。也可以保留完整仓库文件夹，直接打开本目录 `index.html`；按需数据通过本地脚本载入，支持 `file://`。

使用仓库根的 GitHub Pages 发布流程。共享导航和统计引用 `../assets/`，请勿单独把本目录改成网站根。生产包由公共白名单生成，不包含维护源、工具和说明。收藏仍使用原浏览器存储键与 `item-xxxx` 等玩家图鉴 ID；旧收藏与 `#entry=…` 链接无需迁移。

## 按需加载

- 首页只读取约 36 KB 的 `data/bootstrap.js`：24 张武器摘要、分类数量、合法 ID 范围、图片覆盖率及分片清单。没有空闲时下载全库的任务。
- 点击分类或翻页，才读取对应分类的卡片索引。
- 首次全局搜索读取单独搜索索引；仅为当前页结果补齐详情。搜索范围包含原有中文、英文、细分分类、标签和说明。
- 详情按玩家 ID 的数字区间分片，每区间最多 32 条；配方材料和产物只读取关联条目。材料用途与相关制作关系使用独立索引。
- 收藏和比较只读取所选 ID 对应片段。已完成及进行中的请求共用缓存；加载失败有重试入口，过时请求不会覆盖当前分类或详情。
- `data/lazy/` 的文件使用内容 SHA-256 的前 16 位命名；数据改变会自动更换 URL，避免部署后混用旧缓存。HTML 中常规脚本与样式由根发布工具自动加版本参数。

## 维护

维护真源是 `data/catalog.js` 与 `data/world.js` 中的纯 JSON 赋值。它们是已经筛选的玩家数据，网页不会加载，公开包不会发布。不要重新导入游戏原始配置、代码、类名或素材提取路径。

在仓库根执行：

```console
python LDOE_Wiki/tools/update_data.py
python LDOE_Wiki/tools/verify_data.py
python LDOE_Wiki/tools/test_data.py
```

生成器保留所有源记录字段与数值，生成首页摘要、分类/搜索索引、详情分片及配方关系，并精确删除本目录中已过期的生成分片。校验器独立重算全部产物，检查规范化记录、关联、图片路径和 SHA-256；文本校验兼容 Git 的 LF/CRLF 换行转换，图片始终逐字节比较。工具只依赖 Python 标准库，可直接在 Linux CI 使用。

新增源字段必须先补充并审阅维护 schema；未知嵌套字段、原始技术来源路径或无关游戏实现元数据会使校验失败。正常改资料不会更新图片基线。只有明确审阅过新增/替换图片，才执行：

```console
python LDOE_Wiki/tools/update_data.py --accept-images
```

可选浏览器回归需要 Python Playwright 和已安装的 Chrome：

```console
pip install playwright
python scripts/test-ldoe.py
```

设置 `LCZ_BROWSER=msedge` 可改用已安装的 Edge。测试包含首屏请求、分片缓存、失败重试、竞态、收藏恢复、比较、配方计算、变体、深链、手机触控与 `file://`；本地预览不会触发正式访问计数。默认仅在终端输出验证结果；只有明确要求保留诊断产物时才设置 `LCZ_TEST_OUTPUT`。
